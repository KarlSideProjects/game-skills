# 遊戲適配與模型分析

## 格式證據

遊戲工程保存來源指紋、每種文字容器的格式說明和可執行檢查。將「看到可讀文字」與「知道完整記錄格式」分開記錄；NUL、換行或可列印字元掃描的結果只是候選，除非其他證據確認邊界。

分析每個實際存在的容器，記錄：來源檔與區段、字元編碼及字表、結尾與控制碼、指標與長度欄位、壓縮與封包、字庫和排版限制。對照多個相鄰記錄或追蹤遊戲讀取程式驗證推測。只有已觀察到的結構才建立程式規則；未知字節以原值保存。

需要閱讀現有程式碼結構時，遵循工作區的探索指令。模型分析先取最小樣本，將驗證成功的判斷放進適配程式，後續執行只輸出摘要與錯誤位置。

## 最小適配與驗證

優先採用現有遊戲工具，其次才寫專用程式。其他語言公開工程可提供字庫、編碼、函式或指標線索；它們的譯文、來源 hash 或 build assert 不作為繁中翻譯目標或現有鏡像必要條件。版本不匹配時，直接分析使用者提供的鏡像；僅有證據確認缺少必要來源時才請求補檔。Atlas 支援自訂字表及指標回填，Saturn Patcher 處理已完成的檔案修改與補丁封裝；它們不自動辨識所有遊戲的劇本。[Atlas 原始碼](https://github.com/stevemonaco/Atlas)、[Saturn Patcher 作者發布頁](https://segaxtreme.net/resources/sega-saturn-patcher.73/)

固定區塊符合 bundled helper 的限制時，只寫設定。否則在遊戲工程保存 `extract.py` 與 `insert.py`，或延用現有工具與設定，遵循[JSONL 契約](programs.md)。無需先建立外掛框架；第二個真實適配案例出現共同邏輯時再抽取。

驗證順序是：未修改的提取與回填逐位元組一致，修改單筆文字可重新解碼，再測試含新增繁中字形的單句遊戲內顯示，然後才處理全部文本與正式建置。候選字表、地址或函式沒有 xref 支持時標為候選或排除；尚未完成的格式逆向標為工程未完成。壓縮格式若不能重現同一串位元組，保存並比較未修改區塊的原壓縮資料，另驗證修改區塊解壓結果與長度、指標的正確性。

## 中文顯示及特殊容器

中文字庫與腳本必須一起確認。檢查新增漢字能否編碼、是否有對應字形、遊戲是否讀取正確位元組寬度，以及一行的像素上限。單字節英文補丁不代表中文支援；繁簡轉換後同樣需要字形覆蓋檢查。

圖片上的文字採用圖像修改流程，影片上的字幕採用影片流程，與對話 JSONL 分別記錄覆蓋範圍。例如 Cyber Doll 翻譯工程有自訂文字編碼、新字型、UI 圖像與影片修改；Rabbit 還需要調整遊戲資料完整性檢查。這些作者說明可作為逐款研究的線索，不能移植為所有遊戲的通用假設。[Cyber Doll 作者倉庫](https://github.com/ExxistanceDC/Cyber-Doll-English-Translation)、[Rabbit 作者倉庫](https://github.com/DerekPascarella/Rabbit-EnglishPatchSaturn)

Vandal Hearts 的本地研究讀到了英文版 `B_TXT*.DAT` 的字母區段：`A1..BA` 是 `A..Z`，`C1..DA` 是 `a..z`，`A0` 是空格。這僅是特定英文補丁的預覽證據，沒有驗證全部控制碼、指標或中文回填。若這些檔案作為新任务輸入，先重新確認補丁版本及原始位元組。英文作者另有單字節編碼和 VWF 的說明。[作者頁](https://meduza-team.ucoz.net/news/perevod_na_anglijskij_jazyk_igry_vandal_hearts_sega_saturn/2020-11-23-31)
